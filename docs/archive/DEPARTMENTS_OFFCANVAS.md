# Departments: Adding via Offcanvas

This document explains how the Departments "Add" offcanvas works and how to maintain or extend it.

Overview
- The offcanvas contains a small form that POSTS to `/departments`.
- Server-side handling is implemented in `App\Controllers\DepartmentController::store()`.
- CSRF protection uses `App\Core\Csrf` and a hidden `csrf_token` input.

Client-side behavior
- The department code is auto-generated from the department name using a simple acronym algorithm (first letters of words, up to 4 characters).
- The code appears in a readonly field `departmentCode`. The server also generates and validates the code to avoid collisions.
- The Head of Department select is populated from the `employees` table (payroll_number values).
- The Add button submits the form via `form="createDepartmentForm"` so it works from the offcanvas footer.

Server-side behavior
- The `store()` method in `DepartmentController`:
  - Validates CSRF token using `Csrf::validate()`.
  - Trims and validates the department name (required).
  - Checks case-insensitive uniqueness using `Department::existsByNameCaseInsensitive()`.
  - Generates a unique department `code` via `Department::generateCodeFromName()`.
  - Stores the row via `Department::create()` using prepared statements.
  - On success redirects back to `/departments`.
  - On error sets `$_SESSION['flash_error']` and redirects back; you may display this in the view.

Security notes
- All DB queries use prepared statements to prevent SQL injection.
- CSRF protection is mandatory for the form.
- Name uniqueness is checked server-side with a case-insensitive comparison to prevent duplicates like "HR" and "hr".
- Inputs are escaped when rendered in views using `htmlspecialchars()`.

Extending
- Add a modal or endpoint to assign an existing employee as head if needed.
- Add server-side validation rules for allowed characters in name or max length.
- Consider adding an audit trail recording who created the department.

Developer tips
- To change the code-generation logic, update `App\Models\Department::generateCodeFromName()`.
- To change the uniqueness rule (e.g., allow same name in different regions), update `existsByNameCaseInsensitive()`.

Current implementation (2026-08-26)
---------------------------------
- Offcanvas UI
  - Two tabs: `General details` (form) and `Limits` (placeholder content).
  - Form fields: `department_name`, `head_of_department` (select populated from `employees`), and a readonly `department_code` input.
  - The form POSTs to `/departments` and includes a hidden `csrf_token` generated by `App\Core\Csrf::generate()`.

- Department code
  - Client-side: small JS generates a short code on input/open of the offcanvas: first letter of the name (uppercased) + random 3-digit number (e.g., `D123`). This populates the readonly `department_code` field so it is submitted with the form.
  - Server-side: `DepartmentController::store()` accepts `department_code` from POST and saves it if provided. The server no longer forcibly generates a code for each department (previous server-side generator was removed per user request), but the Department model still contains utilities for generating/checking codes if needed.

- Name uniqueness and validation
  - The server enforces case-insensitive uniqueness: `Department::existsByNameCaseInsensitive($name)` uses `LOWER(name)` to avoid duplicates like `HR` vs `hr`.
  - If a duplicate is detected, `store()` sets `$_SESSION['flash_error']` and redirects back.

- CSRF and sessions
  - CSRF token is generated once per page load and reused across the offcanvas form and per-row delete forms to avoid "Invalid CSRF token" issues.
  - `App\Core\Session::start()` is called in `public/index.php` to ensure sessions are active.

- Delete functionality
  - Delete endpoint: POST `/departments/delete` (protected by `AuthMiddleware`).
  - `DepartmentController::delete()` validates CSRF, deletes via `Department::delete($id)`, sets a flash message, and redirects back.
  - The per-row Delete action is implemented as an inline POST form with a JS `confirm()` prompt.
  - The `employees.department_id` foreign key is `ON DELETE SET NULL`, so deleting a department unassigns employees rather than removing them.

- Deployment page
  - `/departments/deployment` shows a table of employees with a `Department Status` column: `Assigned` (shows department name) or `Unassigned`.
  - Bulk-selection checkboxes were restored to work with the table utilities used elsewhere in the app.

- Flash alerts
  - Flash messages are rendered in Falcon-style dismissible alerts for four levels: `flash_success`, `flash_info`, `flash_warning`, `flash_error`.
  - Alerts include icons and a close button that dismisses without a page reload.

Testing checklist
- Open `/departments` and ensure page loads without CSRF errors.
- Open Add offcanvas, type a department name — `department_code` should populate automatically.
- Submit a new department; expect success alert and new row in the table (or verify DB).
- Try submitting a duplicate name (different case) — expect error alert.
- Use the row menu Delete action and confirm — expect success alert and department removed; employees should be unassigned.
- Open `/departments/deployment` to verify employee list and department status.

Notes and next steps
